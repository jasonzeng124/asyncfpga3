## Model

- **Network** (`circ`). The whole physical netlist of a seed is one 7f `Circ`.
  - Nodes 0..8 are the input ports, in C-11c's order: A0, ack_out, data_in[0..2], r1, r2,
    req_in, rst.
  - Node `9+2i` is O6 of physical LUT `i`, a gate with the PHYSICAL INIT on the PHYSICAL pin
    sources A1..A6.
  - Node `10+2i` is O5, with `INIT % 2^32` on A1..A5.
  - Ties are constants (H_TIE).
  - 7 sites give 14 gate nodes. 10 of them are used; 4 are unused O5s, which are included and
    harmless.
- **Link to Bn** (`stepK_circ`). The generic ternary step at node `pidx i o` IS Bn's
  `OnNetlist.excK N s w i o`, the physical Kleene excitation. So this is exactly the
  netlist Bn checked against B's cell functions. Logical names come from Bn's checked map
  `Seed.m` (`phys`).
- **Runs.** These are 7f's `Run` / `Bounded D W`, unchanged:
  - GMW gates;
  - one read time per routed pin (H_WIRE_CAUSAL), so per-pin routing skew, including the A0
    fork, is inside the model; Bn's commuting square did not have it;
  - wires at most `W` steps old;
  - a gate shows a steady LUT value within `D+1` steps.

  `D` and `W` are free parameters: every theorem holds for every delay assignment within
  them.
- **Schedules with checked certificates.**
  - A phase is a window vector `u` (`x` exactly on the inputs that change), a final vector
    `a`, and a certificate pair `(s, r)`.
  - `chk` decides four things: `s` is closed under the window step (`stepK u s ⊑ s`);
    `r = iterL a 3 s`; `r ⊑` the next phase's `s`; and the lengths.
  - The certificates were generated by running the same functions. They are not trusted:
    any closed `s` is sound, and `r` is recomputed. `neg_cert_closure` shows that a
    weakened `s` fails.
  - The timing side is `TimesOK`: `S ≤ F` and `F + 3(D+W+1) + W ≤ S_next` (7i's spacing).
  - Generic glue proves 7i's `Closed`/`Links` from the check (`build_ok`), applies
    `phases_sound` (`build_good`), and reads the result on the lists and then on logical
    nodes (`good_holds`, `holdsL_T`, `schedule_holds`).
  - Function iteration is related to list iteration by `iter_lt` / `iter_ge`, given `WF`:
    every pin reads a node inside the network (decided).
- **Expected tables** (`expTables`, the same for all seeds). They were written from the cell
  specifications, not copied from a run:
  - `c = ~rst·C(req_in, ~ack_out)`;
  - the latch is transparent while c = 1;
  - the arbiter states are 7b's `idle1/own1/served1/done1` and their client-2 mirror;
  - in an A table, `x` exactly on the nodes meant to move in that window.

  The certificate check compares the logical projection of every (A, B) list with them.

## Theorems (namespace `Formal.Cells.TernaryOnBits`)

**(1) Reset.** `reset_s1..s4` (via `reset_settles`):
- **Hypotheses.** Any power-up state, any waveform on every input, and rst = 1 from `F`.
- **Conclusion.** Every bounded run has c = 0, A1 = A2 = 0, q = 1, g2 = 0 from
  `F + 3(D+W+1)`, for ever.
- **Not reset.** g1 and R0 follow r1, since they are combinational. The three latch bits
  stay `x`: `bd_link` has no data reset, so data_out is undefined until the first
  transaction.

**(2) Transactions.** `txn_s1..s4`, from `schedule_holds` with `cert_s1..s4`:
- **The schedule** has 14 phases, starting from all-`x` power-up:
  - reset (rst = 1, controls 0, data anything);
  - reset release, during which data becomes 101;
  - one four-phase link transaction: req_in up, ack_out up, req_in down, then ack_out down
    with data_in changing 101 → 010 in the same window;
  - client 1's arbitrated transaction: r1 up, A0 up, r1 down, A0 down;
  - client 2's arbitrated transaction: the same with r2.
- **Conclusion.** Every bounded run whose inputs follow the schedule (`Follows`) with
  `TimesOK` times satisfies `HoldsT … expTables ts`. On each of the 19 logical nodes:
  - **During each window, from S to the next S**, the run is admitted by the A table. Every
    node that is definite there never moves: **hazard-free**. Examples:
    - c holds 1 while ack_out rises;
    - data_out holds 101 while c falls (phase 4) and **while data_in changes** (phase 5,
      latch closed);
    - g2, A2 and A1 stay 0 while r1 rises;
    - A1 holds 1 while r1 falls;
    - q holds through A0 edges.
  - **From `F + 3(D+W+1)` to the next window** (for ever after the last), the run equals
    the B table. Every node is definite at every phase end, except the three latch bits
    before the first transaction.
- The results for all four seeds are identical in logical terms. Their physical
  certificates differ.

**(3) Contested.** From the idle state after phase 9 (`idle1..4`; `contestB` checks it is
phase 9's B list, binary stable, and with a fixed A/B at 3), r1 and r2 rise in one window.
- `contested_x_iff`: the A-then-B result at a gate node is `x` iff the node is the physical
  q, g1 or g2. The logical table is decided: R0 = 1, A1 = A2 = 0, link unchanged.
- `contested_exact_s1..s4`: for every physical gate node `n`, **some bounded run never
  settles at n iff n ∈ {q, g1, g2}**.
  - The runs start in idle; inputs stay inside `uC`, so only r1 and r2 move, and they are 1
    from step 2.
  - The direction for the other nodes is 7f: every definite node settles in every bounded
    run.
  - The witness is 7l's `wv`: unit gate delay, one clean edge on both requests at step 1.
- `contested_exact_fifo` gives the same iff with 7l's FIFO witness (`D = 0`, `W = 1`,
  non-reordering wires, requests glitching inside `uC` before `T0`).
- `contested_nodes_s1` checks non-vacuity: q, g1 and g2 are three distinct gate nodes, and
  the network has 23 nodes.

**Negative controls** (each check can fail):
- `neg_mut_init`: Bn's MutInit (seed 1, ugrant INIT bit 36 flipped) fails the certificate
  check.
- `neg_table_hazard`: claiming c is glitch-free (definite 0) during the req_in-rise window
  is refuted.
- `neg_cert_closure`: an A certificate with c = 0 instead of `x` fails the closure check.

## What did not work / limits

- **Open environment.** The theorems assume the inputs follow the schedule: the environment
  obeys the four-phase protocol with the stated spacing. No closed-loop environment is
  modelled. "Hazard-free" here means: with `x` on exactly the changing inputs, the A-definite
  nodes never move, for every delay assignment.
- **Settling bound and spacing.** The settling bound `3(D+W+1)` is in model steps. `D` and
  `W` are not tied to SDF or prjxray numbers. The spacing `F + 3(D+W+1) + W ≤ S'` is a
  hypothesis on the environment's timing.
- **O5/O6 as separate nodes.** O5 and O6 of one LUT6_2 (g1/g2, R0/q, q0/q1) are separate
  gate nodes with independent pin reads. For soundness, (1) and (2), this is only an
  over-approximation. For the exactness witnesses in (3), the run may let O5 and O6 see the
  shared pin at different times. Silicon shares the input buffer, and the skew after it is
  small but not zero. The `x` on q does not depend on this: q is its own node. A refinement
  that forces equal reads for O5/O6 of one site is not done.
- **Witness assumptions.** As in 7l, the B witnesses need transport, not inertial,
  feedback: they carry 1-step pulses. They also need non-FIFO reads (`wv`) or glitching
  requests (`tv`). Mid-rail levels and metastability are outside the binary model. The
  "never settles" run is the binary shadow of metastability, not a model of it.
- **Scenarios not in the schedule.** Two scenarios are not exercised:
  - the A0-fall with a waiting client (7i's early-ack case under fork skew);
  - the tie followed by a server ack.

  Each is one more spec list plus certificate: mechanical, about 30 min each.
- **Other designs.** Only `link_arb` is covered. Other designs need C's `fasm2lean2` output
  and a `Seed.m` map (Bn's item 3).
- **Proof style.** Tables and certificates are per-seed literals. A generator script was
  not committed; the certificates come from `#eval` of the same Lean functions, in a
  scratch file.

## Verdict

**Works.** The generic theorems of 7f, 7i and 7l now run on the whole routed netlist of all
four seeds as one network over physical nodes, with per-pin routing skew. The three asked
results are proved:
1. reset settles from any power-up, for every delay assignment;
2. a full link transaction and two arbitrated transactions are hazard-free and settle to
   definite outputs at every phase end;
3. the contested case is `x` exactly on q, g1 and g2, and that `x` is realised by a bounded
   run that never settles.

The kernel checks cost about 4–5 s per seed.

What it buys:
- A verified, cheap checker (`certB` / `contestB`) for "this routed bitstream is
  hazard-free under this protocol for every GMW delay assignment".
- The one finding: data_out is undefined after reset (no latch reset), which is harmless
  only because no consumer reads data before the first req.

To extend:
- per-site shared O5/O6 reads, for sharper witnesses: about 1 day;
- more scenarios: about 30 min each;
- a script that emits certificates and tables for any C-imported design: about 1 day.

## Fidelity per primitive

- **LUT6 / LUT6_2.** The physical INIT on the physical routed pins, from the bits.
  - Ternary side: `lutK`, under H_KLEENE_LUT; equal to the per-mux tree here because Bn's
    `read_once` holds.
  - Binary side: `lutB` / GMW, via 7f's `Run`.
  - O5 = `INIT[31:0]` on A1..A5, as a separate node (see the O5/O6 limit above).
- **Routing.** One read time per (gate, pin), at most `W` steps old in bounded runs. This
  covers pure, inertial and non-FIFO wires and per-branch fork skew. The witnesses use
  transport delays.
- **Feedback** (C-element, latch, arbiter q). This is a pin whose source is the LUT's own
  output node. It is treated like any other routed pin.
- **Ties.** Constants (H_TIE).
- **IOB/IOI.** Ports are input nodes; this is C-11c's identity bypass. Input waveforms are
  arbitrary inside `u` during a window: runts and glitches are allowed.
- **Time.** Discrete steps, as in 7f.
