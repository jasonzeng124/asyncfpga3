# C-8t: a joint, non-vacuous witness for `gcd_hw_circuit_safe''`

Shard C, probe 8t, 2026-10-27. About 1.5 h of work (plus build waits).

**Status: DONE.**

## Verdict

**The hypotheses of `gcd_hw_circuit_safe''` are jointly satisfiable, by a run that delivers a
result.** This is proved in Lean, kernel-checked, with no sorry, no extra axiom and no
native-decide. There is an explicit circuit run of the concrete 465-channel gcd_hw network
on a = 12, b = 18 such that all of the following hold at once:
- H_CELLS (all 367 operators meet their gate models);
- H_BUNDLE (all 465 channels are `Held`);
- H_START_ONCE;
- H_WALK (with an explicit complete token run `y`);
- out0 closes a token (its acknowledge falls), and that token carries 6 = gcd 12 18.

The answer 6 is not 0, 1, a or b. Applying the safety theorem to this run gives 6 again
(`gcd_hw_witness_consistent`).

The same run is also a witness for 8s's `gcd_hw_circuit_safe3`, whose hypotheses are only
H_CELLS, H_BUNDLE and H_START_ONCE (`gcd_hw_joint_witness3`, `gcd_hw_witness3_consistent`).

This answers the audit's P4 point ("no joint witness exists for a gcd_hw network"). It also
answers 8m's admission that "the all-quiet run meets every hypothesis and latches nothing".

```
theorem gcd_hw_joint_witness :
    ∃ ch : Fin NC → Chan,
      (∀ o : Fin NO, Cell ch (srcV 12 18) (opAt o)) ∧        -- H_CELLS
      (∀ c, Held (ch c)) ∧                                   -- H_BUNDLE
      (∀ t, cnt (riseB (ch start).req) t ≤ 1) ∧              -- H_START_ONCE
      (∃ y, Good 12 18 y ∧ WalkOK (σY 12 18 y) (omOf 12 18 y)) ∧   -- H_WALK
      (∃ k e, TokAt (ch out0) k e ∧ (ch out0).dat e = 6)     -- out0 latches 6
```

These are literally the hypotheses of `gcd_hw_circuit_safe''` instantiated at a = 12,
b = 18 (`#check` output in `Wip/C8t/Axioms.lean`). Axioms: propext, Classical.choice,
Quot.sound.

## How the witness is built

**1. The circuit run** (`formal/tools/capwit/sim.py`, then `gen_data.py` writes
`CapstoneWitnessData.lean`).
- It is a synchronous unit-delay simulation of exactly the gate models in `CapNet.Cell`:
  - every modelled gate (request wires, C-elements, steer and mux LUTs, link `c`, arbiter
    grants, ack wires and ORs) takes at t+1 its excitation function of the signals at t;
  - a C-element holds while its inputs disagree;
  - buses are the models' zero-delay functions of the same tick;
  - a link's latch is transparent while its `c` is high;
  - when both inputs request in the same tick, the arbiter grants x (the model leaves the
    winner free).
- The environment:
  - the three `Src` sources (a, b, start) each offer one token, then never re-request (`Src`
    is an unbounded inertial delay, so this is allowed);
  - the sinks acknowledge after one tick.
- The run goes quiescent after 476 ticks, with 2252 request/acknowledge toggles.
- out0 is acknowledged-low (closes) at tick 473, carrying 6.
- Coverage of the run:
  - 407 of the 465 channels carry a token;
  - 141 of the 175 links, and every fork, join, steer and mux, are active;
  - 8 of the 9 arbiter stages pass a token, and 3 of them grant both inputs;
  - the idle stage is `acc251`, stage 1 of the end cascade, used only by the a = 0 / b = 0
    early returns.
- `sim.py` also re-checks every model field in Python, but this is untrusted. The kernel
  re-checks everything.

**2. Event-list representation and checker** (`CapstoneWitnessLib`, generic in the network).
- A binary signal is given by its list of toggle steps; `bv L t` is the parity of `#{e ∈ L, e < t}`.
- A bus is given by an initial value plus change points; `nv d L t` is the last change before `t`.
- `CD` packs one channel, plus its producer's internal traces (link `c`, mux `j0 j1`,
  3-way mux `j0 j1 j2`, arbiter `g1 g2`). Every existential of `Cell` is therefore keyed by
  the producer's output channel.
- `kChk` is a Boolean checker per operator kind, and `kChk_sound : kChk cd sv k = true → Cell (wch cd) sv k`
  is proved for all 12 kinds. Two lemmas make the finite checks cover every `t`:
  - "moves only to f(previous tick)" fields are checked at the toggle steps of the moving
    signal (`step_of`: a signal is constant off its list);
  - pointwise fields (data functions, `H_ARB_EXCL`, latch transparency) are checked at 0 and
    right after every change point of the signals involved (`pw_ind`).
- `heldChk` / `held_of` do the same for `Held`.
- `once_of` turns a 2-element start toggle list into H_START_ONCE for all `t`.

**3. Kernel checks** (`CapstoneWitnessCells`, 42 s, 1.2 GB peak).
- `ops.all (kChk cdA (srcV 12 18))`, in 4 chunks, gives `w_cells`.
- `cds.all heldChk` gives `w_held`.
- The start toggles are `[0, 99]`, which gives `w_start_once`.
- `TokAt (chW out0) 0 473` and `dat = 6` give `w_out0`.

**4. The token run `y`** (`CapstoneWitnessTok`, `CapstoneWitnessRun`; the run file is
generated by `Wip/C8t/RunGen.lean` via `Wip/C8t/gen_run.sh`).
- `TL` is a list-form traced state: store, consumed and produced histories, each a list of
  252 lists.
- `tstepL_ok` / `texecL_ok` prove that it agrees with `CapSafe.tstep` / `texec` under `ofL`.
- The run fires the first enabled rule each time: 212 firings, certified in 9 chunks of 25
  as `texecL Y_k ls_k = some Y_(k+1)`, with literal sparse intermediate states.
- The final store is `lmap [gcd 12 18] T1 = final 6`.
- `good_of_texec` (the proof of `good_exists`, applied to a given run) gives
  `Good 12 18 yW`.

**5. H_WALK** (`CapstoneWitnessWalk`).
- `walkChk σ om F s` follows the walk for at most `F` steps, checks `WalkOK`'s
  arbiter-arrival condition at each step, and requires that the walk has ended.
- `walkOK_of` proves it sound, using the fact that the walk is constant once `cur = none`.
- It is decided for `yW` with F = 80. walkcheck reports 71 steps and 12 arbiter arrivals.

## Fidelity

- **What the witness exercises: the hypotheses exactly as Lean states them.** The run is a
  run of the gate models (`Cell`), not of silicon. Unit delay is one admissible choice of the
  unbounded SI/DI delays. The arbiter's tie-break toward x is one admissible resolution of a
  model that leaves the winner free.
- **H_AMERGE_RTZ (the thin stage-1 race found by 8l)** holds in this run. It is part of
  `AMerge` and is checked by `kChk`.
- **H_BUNDLE holds for the zero-delay buses of the models.** This is the formal object.
  Whether physical buses meet it is §3's tcheck question, and also 8w's refinement finding.
  The witness says nothing about that.
- **H_START_ONCE holds because the start source offers once.** That matches one invocation
  of the rig, not the rig's repeated invocations (8s2's topic).

## What it does NOT show

- **It covers one input pair and one schedule.** It is non-vacuity, not a test of the theorem
  on other inputs and not a liveness result. It does show that the hypotheses are not
  contradictory, and that they do not force the all-quiet run.
- **It does not show that the hypotheses hold of the hardware.** A unit-delay model run is not
  a GLS or a board run.
- **It does not exercise arbiter stage `acc251`.** That stage is reachable only through the
  degenerate a = 0 / b = 0 paths.
- **It does not exercise 58 data-dependent channels**, the untaken branches for this input.

## Surprises

- **No hypothesis conflicted.** The plainest schedule, all delays 1, met every field of every
  gate model, `Held` on every channel, and the arbiter RTZ condition at once. No delay tuning
  was needed.
- **Repeated tokens did not produce a wrong value in the unit-delay run.** An untrusted Python
  side experiment (not claimed) let all three sources offer 2, 3 or 5 tokens, which the `Src`
  model allows. The unit-delay run then pipelined the invocations and latched 6 every time,
  and only H_START_ONCE failed.
  - 8r's argument that H_CUT breaks without H_START_ONCE relies on other delay choices.
  - This experiment neither confirms nor refutes it. It only shows that the unit-delay
    schedule does not hit that race.
- **Kernel cost was small for the circuit side, larger for the token run.**
  - Checking 367 operators over about 2300 events took 42 s, because each condition is
    checked only at its own signal's events.
  - The token run's chunk certificates cost the most, at 2.8 GB.
