## Verdict

### 1. `gcd_hw_live`'s hypothesis set describes no physical run (`CapstoneLiveNdStart`)

**`start_never_closes`.** Assume H_CELLS, H_BUNDLE, H_START_ONCE and H_BOUNDED_DELAY exactly
as `gcd_hw_live` states them. Then `start`'s acknowledge never falls: the start token is
never released.

The generic form is `src_once_never_closes`:
- A protocol channel driven by a `bd_src` LUT that has a settle bound, and that is offered at
  most once, never closes.
- Reason: after the close, the LUT is excited to offer again for ever.

Argued, not mechanised: in such a run the first link stage behind `start` never completes its
input handshake. So `out0` never closes. But H_NO_DEADLOCK + H_FIRING_BOUND force `out0` to
close. So `gcd_hw_live` is at best vacuous, and H_NO_DEADLOCK as 8u stated it should not be
proved in that context.

**Fix:**
- `start`'s LUT gets a bound only before its first offer (**H_START_ENV**, `StartEnv`).
- Quiescence ignores that LUT after the first offer (`Quiet2`, `QuietS`).
- Every other gate keeps H_BOUNDED_DELAY (**H_BOUNDED_DELAY'**). That includes the
  free-running `a`/`b` sources.

### 2. The firing bound on a state that can be bounded (`CapstoneLiveNd`)

8u's H_FIRING_BOUND counts changes of the whole of `gsAt`. That state includes things no
gate model constrains:
- `itr p k` for internal indices an operator does not use (all of a fork's `itr p`);
- buses of idle channels (H_BUNDLE holds a bus only mid-transaction).

Junk there may flip at every tick while every hypothesis holds. So no `N` that is
independent of the delays can hold for all runs. (This is not mechanised: it would need a
full run meeting H_BOUNDED_DELAY.)

**Fix:** the ranking state is the projection `pj`:
- every request and acknowledge;
- the used internal nodes (`nI`: mux 2, muxn 3, amerge 2, link 1);
- each bus only while its request is high;
- plus the flag "start offered".

Results:
- `gate_pj`: every gate's excitation and output read only `pj`.
- `frozen_quietS`: a projection frozen for `H + 1` ticks is quiescent (arbiters through 8u's
  `gcd_hw_arb_settle`).
- `firing_bound`: H_OFFER_BOUND `M` (every channel offers at most `M` tokens before the first
  `out0` close) implies at most `1168 * (2M + 1)` projected changes. Here 1168 = `nBits` =
  2 · 465 channel bits + 238 internal nodes.
  - Each bit's rises are bounded by one channel's offers. An acknowledge follows its request.
    Each internal node follows a request (`follow_rises`: mux joins, 3-way joins, grants,
    link C-element).
  - Then transitions ≤ 2 · rises + 1.
- `gcd_hw_live_nd`: the repaired reduction.

### 3. Every channel offers at most `4L + 11` tokens (`CapstoneLiveNdOff`)

H_OFFER_BOUND for all 465 channels, at all times. It comes from 8u's spine bound
(`W c ≤ L`) and two kinds of local rule, each proved for each operator kind.

**up (no token invented):**
- fork, join, steer and link outputs: `off c ≤ off(input)`;
- arbiter and mux outputs: `≤ off x + off y`;
- 3-way mux output: `≤ off x0 + off x1 + off x2`.

The steer case uses H_BUNDLE (`and_rises`).

**dn (backpressure): a channel offers at most one more token than it has seen acknowledged:**
- fork, join, bjoin, mux, muxn and arbiter inputs: `off c ≤ off d + 1`, where `d` is the
  output whose acknowledge the input acknowledge follows;
- link input: `+ 2` (the C-element follows the inverted output acknowledge, `link_c_nack`);
- steer input: `≤ off t + off f + 1`.

**The certificate.** The certificate `cert` (`CapstoneLiveNdCert`, generated by
`Wip/C8z/offcert.py`, 15 rounds) gives each channel:
- a rule;
- a bound `al * L + be`;
- a round number. Each rule may use only channels of strictly smaller rounds, so the
  derivation is acyclic.

How it is checked:
- The kernel checks it (`certOK`, `decide +kernel`).
- `off_cert` proves the bounds by strong induction on the round.
- Maximum: `al ≤ 4`, `be ≤ 11` (`cert_small`).

**Free-running sources.** The free-running `a`/`b` sources need no environment hypothesis.
Backpressure from the joins that wait for the single `start` token bounds them (`dn` rules
up the fork chain).

**Negative controls** (`Wip/C8z/MutCert.lean`): the checker rejects:
- a tightened constant;
- a wrong operator rule;
- a same-round (cyclic) derivation.

### 4. H_WALK_ENDS proved (`CapstoneLiveNdWalk`)

**`walk_ends`.** For the token run `y` from 8s's `good_run`, the spine walk has ended by
`Lrun y = 1 + Σ_spine (A y c + 1)`. Here `A y c` is the number of tokens the complete run
consumes on the GcdHw channels behind spine channel `c`. So `Lrun y` = 68 + Σ_spine `A y c`:
the consumed spine tokens, each counted once per circuit spine channel that stands for it.

Proof:
- While the walk is alive, `Σ_spine W ≥ p`.
- 8s's `walk_sim` gives `W c ≤ A x c + 1 ≤ A y c + 1`.

### 5. The resulting theorem

```
theorem gcd_hw_live_final (a b H : Nat) (ha : a < 2 ^ 31) (hb : b < 2 ^ 31) (ch) (itr)
    (H_CELLS) (H_BUNDLE) (H_START_ONCE) (H_BOUNDED_DELAY' H) (H_START_ENV H)
    (H_ARB_UNCONTESTED_BOUNDED H) (H_NO_DEADLOCK') :
    ∃ y, Good a b y ∧ ∃ e, e < (1168 * (8 * Lrun y + 23) + 1) * (H + 1) ∧
      TokAt (ch out0) 0 e ∧ (ch out0).dat e = Nat.gcd a b
```

- H_WALK is discharged by 8s (`gcd_hw_walk` / `walk_ok`) and H_WALK_ENDS here. Neither is a
  hypothesis any more.
- `gcd_hw_live_bounded` is the same with `L` free, under H_WALK and H_WALK_ENDS `L`.

**H_NO_DEADLOCK'** (open), exactly:

    ∀ t, #out0 closes before t = 0 →

In words: before `out0` closes, either a gate other than `start`'s LUT is excited, or `start`
has never been offered and is enabled but not requested.

## What it does NOT show

- **H_NO_DEADLOCK' is not proved**, so `gcd_hw_live_final` is still not a liveness theorem
  for the circuit. It is one network obligation away. The plan from 8u stands:
  - simulate the walk by the circuit;
  - at the walk's current channel, show that its producer is excited once data and condition
    inputs have arrived and the output stage is empty.

  Two pieces are now available for that:
  - the offer counts (an excited input that is never consumed would contradict nothing here);
  - the projection lemmas.

  The hard part is "a non-spine input the walk needs has arrived". That is a data-side
  counting invariant (each non-spine channel's offers are ≥ the walk's demand). It is the
  converse of `off_cert`'s upper bounds, and it is not written.
- No consistency witness for H_BOUNDED_DELAY' + H_START_ENV + H_CELLS on the concrete network
  in Lean. 8t's witness runs the sources once, which violates H_BOUNDED_DELAY' for `a`/`b`.
  `ndsim.py`'s free-running runs are the Python evidence.
- The bound is loose. 1168 · (8L + 23) counts every bit at every offer. Measured changes are
  about 10× smaller.
- One invocation only (H_START_ONCE). Delays are in ticks of the per-gate bound `H`.
  H_DATA_COMB as before.
- `start_never_closes` shows only that `start` hangs. It does not mechanise the step
  "start hangs ⇒ `out0` never closes" that makes 8u's set vacuous.

## Surprises

- 8u's hypothesis set was contradictory in spirit. The `start` LUT was given a settle bound
  while being forbidden to fire twice. The two only coexist if the first token is never
  released.
- The firing bound needed no simulation at all. Purely local up/down rules, rooted at the
  spine, bound every channel, including the free-running `a`/`b` sources: the backpressure
  chain ends at the bjoin that waits for `start`. 465 channels resolve in 15 rounds.
- H_WALK_ENDS fell out of 8s's simulation relation in about 60 lines.
