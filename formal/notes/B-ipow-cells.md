# B-ipow-cells: the cells ipow_ps uses, and H_CELLS for C's ipow network from cell contracts

Probe Bipw (shard B, PROGRAM.md goal 3: a second kernel), 2026-10-29. One new Lean file,
`formal/lean/Formal/Cells/IpowCells.lean` (585 lines, core only, checks clean). No route, no
board, no toolchain run (`$TC` and yosys do not exist in this container): nothing below is a
routed number, and the DSP48E1 mapping is read from the build scripts, not from a synthesized
netlist.

## 1. How ipow_ps's kernel is built, and what I read

- `cells/hw/build_hw.sh ipow_ps` runs `python3 bdc/emit.py
  build/frontend/ipow/comp/handshake_transformed.mlir --no-top -o build/gen/ipow_kernel_ps.v`
  (no knobs). There is no committed Verilog fixture under `bdc/` or `kernels/`. I ran the same
  command on the committed MLIR fixture (`cloud/fixtures/frontend/ipow/comp/`), with every
  `BDC_*` knob unset as `formal/tools/dfimport/check.sh` pins them, writing only to
  `/tmp/claude-0/probes/Bipw/ipow_kernel.v` (md5 `4f1a75ca`, module `bdc_ipow`, "67 matched
  delays"). bdc was used read-only; `git status` shows nothing written in the repo.
- C's network: `Formal/Net/IpowCapNet.lean` (C-8y, generated by `formal/tools/capnet/capnet.py`):
  101 channels, 83 operators. Its kind counts are re-checked by kernel `decide` here
  (`ipow_kinds`).
- `cells/hw/ipow_ps.v`: DSP48E1 inference is ON by default (`BD_DSP`); the environment is the
  PS7 AXI register slave plus one `bd_fork` for b, e, start (not a `bd_src`).

## 3. Each cell's share of H_CELLS: contract, theorem, timing

`Contract ch sv nx k` (Lean) per operator kind. "Bound" = the contract names the generated LUT
(`Ops.Gen.genF` on C-11's yosys import) and Lean proves C's field from it. Every feedback LUT
carries `FbCel`: H_LUT_SI (physical `LutFb`, reads the feedback pin), H_FB_ROUTE
(`BoundedDelay lo hi`), reset agreement, **H_RT_FB** (`RespAfter hi`: non-feedback pins change
only after the output has been stable for `hi`). `FbCel.si` (via C-10k's `si_of_resp`) turns it
into the SI gate.

## 4. What ipow uses that gcd_hw does not, and what B is missing for it

- **DSP48E1 (two 32x32 multiplies: `umuli1` = b*b, `uselect0` = r*b).** gcd has no `muli`
  (every gcd multiply is strength-reduced). In the formal chain the multiplier enters only
  through H_DATA_COMB (a zero-time function in `Join.dat`) and H_BUNDLE (the matched delay 64 /
  118 must cover the cone). Missing on B's side, in order: (1) a digital DSP48E1 primitive model
  in the combinational configuration yosys uses (A/B/M/P registers off), as a relation with
  per-arc delay bands; prjxray-db's DSP timing coverage must be checked first; (2) the function
  equality of the mapped cone (DSP cascade + LUT adders) with `muli` mod 2^32 (an H_COMPUTE_FN
  instance, like C-11's cell imports, needs yosys output); (3) the cone's max delay against the
  `bd_delay_gated` minimum (H_COMPUTE_DELAY, rule A), now across a hard block whose internal
  arcs are not in the LUT/route model; (4) output hazards: a combinational multiplier glitches
  until settled, which is harmless only inside the bundling window (B's `Bundling.capture` form
  applies unchanged once (3) holds). None of this exists in A, B or C.
- **A 5-input join (`bd_ctree N=5` in `uselect0`).** gcd's two-level trees are in forks (N=5, 6)
  and its fused joins stop at N=4. Same cell, same gap: H_CTREE_ATOMIC is used once here;
  `CTreeExact.tree_box_exact` is the B result, unbridged.
- **`andi` and `cmpi eq` on 1-bit operands inside a fused unit, and `>>>` by a channel
  operand.** Ordinary yosys LUT logic, the same H_COMPUTE_FN gap as gcd's fused units.
- **Source-chain constants joined into compute units** (4 operands on 3 units). gcd has the
  same pattern; it is now proved harmless for H_CELLS (`join_of_contract`), but the two `bd_src`
  inverter rings and `ufork7`/`ufork8` are cells of the routed design with no model at all
  (their H_RT_FB and pulse widths are unstated; they matter for liveness, not safety).
- ipow uses **no** `bdc_muxn3` and **no** arbiter cascade (`ipow_no_muxn`), so gcd's two worst
  unbound cells are absent.

## 6. What it does not show

- That any routed ipow_ps meets the contracts. H_RT_FB is per-route. C's kcheck has 4 ipow
  routes (`formal/tools/kcheck/results/ipow`, rules A/E/F/H/I/J, 3186 tcheck instances per
  route); I did not check whether those include Rc rows for ipow's C-elements, nor map them to
  the operators here.
- The non-vacuity run is all-quiet: it shows the 83 contracts, H_BUNDLE and H_START_ONCE are
  jointly satisfiable, not that a token run satisfying them exists (liveness, as for gcd).
  `fbCel_witness` shows the timing contract is met by a switching cell, one cell at a time.
- H_SEL_PIN, H_DELAY_LUMPED, H_CTREE_ATOMIC, the arbiter fields, the data fields and H_WIRE_DI
  remain hypotheses in the contract; B's theorems for them (column 5 of §3) are in B's
  per-pin/window models and are cited, not bridged. Only the feedback-wire model is bridged.
- `LutFb` (a LUT output changes only to the function of its pins one tick earlier) is C's
  H_LUT_SI abstraction. B's own LUT model (`CElemTiming.Loop.H_LUT`, a window delay of the
  excitation) does not imply it; bridging the two is open.
- The mux's request chain is bound on `bd_mux_W2` (DELAY 2 in the yosys target); ipow's
  instances have DELAY=12. The chain is the same OR for every length; its length matters only
  for H_BUNDLE.
