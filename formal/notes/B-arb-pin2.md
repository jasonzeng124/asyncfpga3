## Model

The model is ArbPin's, unchanged:
- `bd_arbcell` with its real INITs;
- every pin, including the q feedback, has its own read map within a window, sampled
  non-monotonically (no FIFO);
- `Transport` means every window has width 0 (fixed delays).

Times are Int ps, and requests are single steps.

## Part 1: the mirror cases

### The side swap

`cswap` maps a behaviour of box `B` to a behaviour of `swapB B`:
- **Map.** Requests `(r1, r2)` become `(r2, r1)`, `q0` becomes `!q0` and q becomes `!q`.
  Side 1's pin windows trade places with side 2's, and q→O5 trades with q→O6.
- **Proof.** Three INIT identities, each checked over all 8 input cases: `stF_swap`,
  `gr1_swap`, `gr2_swap`.
- **Transfer.** `all_excl_swap`, `all_transport_swap` and `cex_swap` carry exclusion and
  counter-traces across the swap, in both directions.

So each ArbPin window has an exact mirror, with the same hypotheses mirrored:

| scenario | per-pin (exact over the box) | transport (exact) |
|---|---|---|
| both rise, q0 = 1 | `sd_box_iff`: QUIET `e1+A1 ≤ e2+a2`, or COMMIT `e2+A2+L ≤ e1+a1` with no late overlap ¬(c6<C5 ∧ max(e2+b2, e1+b1) ≤ e2+A2−1+C5). H_LOOP2; H_QWIN' `c6<C5 ∧ c5 ≤ C6+1` | `sd_transport_iff`: same right-hand side |
| r1 falls, r2 rises, q0 = 1 | `o2_box_iff`: ¬O1Ov (swapB B) e2 e1 (H_LOOP_WIN) | `o2_transport_iff`: ¬O1OvT (swapB B) e2 e1 |
| r2→r1 handover (r1 high, r2 falls at f, q0 = 0) | `h21_box_iff`: ¬H12Ov (swapB B) f (H_LOOP_WIN); closed form `h21Ov_closed` | `h21_transport_iff`: **C6 ≤ c5 ∨ B2 ≤ a2 + c5** |

The mirrors also get non-vacuity results:
- `sd_nonvacuous`: every behaviour of `boxS` is exclusive, and side 2 is granted.
- `h21_differs`: the mirrored finding. With q→O6 surely faster than q→O5, every transport
  behaviour is exclusive, but a per-pin behaviour overlaps.

New closed forms for ArbPin's windows:
- `h12Ov_closed` (handover, per pin);
- `o1OvT_closed` (opposite sense, transport);
- `o1Ov_closed` with `O1FallC` (opposite sense, per pin = transport part ∨ fall part).

### New: both requests fall (`dd_*`)

Setting: q0 = 0, so side 2 holds the grant. The waiting r1 withdraws at `e1` and r2 releases
at `e2`. ustate can read the set `r1·~r2` only during `[e2+a2, e1+A1)`.

- **`dd_before`.** In every behaviour, q = 0 before `e2 + a2`.
- **`dd_quiet` (QUIET).** If `e1 + A1 ≤ e2 + a2`, q never moves, so exclusion holds.
- **`dd_excl` (sufficient, every per-pin behaviour).** Assumes H_DDLATE: `B1 ≤ A1 + c5`.
  Exclusion holds if ¬DDOv. DDOv means: there is an instant `t` before both grant-request
  reads can show the falls, and a set instant `x ≤ t − c5` that O5 can read, with an O6 read
  ≠ `x`.
- **`dd_runt_cex` (necessity, NON-monotone).** Assumes H_NOFORCE (`e1 + a1 ≤ e2 + A2`: the
  set is never forced) and H_LOOP_WIN.
  - At the single instant `x`, ustate reads r1 late and r2 early; at every other instant it
    reads the reverse.
  - q is 1 at `x` only, because the loop skips `x`.
  - O5 reads that 1 and O6 a 0, so both grants are high.
- **`dd_box_iff`: exclusion ⟺ ¬DDOv**, exact under H_DDLATE and H_NOFORCE.
- **`dd_closed`.** DDOv ⟺ the set window is nonempty ∧ `e2+a2+c5 < e1+B1` ∧
  `a2 + c5 < B2`, or the degenerate variant with c5 = c6 = C6. So the both-fall race fails
  exactly when the r2→r1 handover's κ inequality fails.
- **Mirror.** `dd2_box_iff` covers q0 = 1.
- **Non-vacuity.**
  - `dd_nonvacuous`: QUIET does not hold and the hypotheses do, every behaviour is
    exclusive, and in a transport behaviour q moves.
  - `dd_instance`: a box where the runt counter-trace overlaps.
- **Data.** 248 of the 252 routed rows satisfy H_DDLATE on both sides. All 4 failures are
  BOX rows.

**Not covered** for both-fall:
- the forced-set regime `e2 + A2 < e1 + a1`. Here r2's release is surely seen before r1's
  withdrawal can be: a handover, then a withdrawal. In 4-phase use that is the r2→r1
  handover followed by r1's return-to-zero.
- the transport-only window.

Both-fall is outside the 4-phase protocol anyway, because a waiting requester does not
withdraw.

The last single-step class is (r1 rises, r2 falls, q0 = 1) and its mirror. It starts in an
inconsistent state, with the cell in reset and q = 1. **Not covered.**

### κ conditions at every request gap (section 5)

Each condition below gives exclusion for **every per-pin behaviour** (no FIFO), at every
gap:

| check | condition | theorem |
|---|---|---|
| r1→r2 handover | `B1 ≤ a1 + c6` | `h12_kappa` |
| r2→r1 handover | `B2 ≤ a2 + c5` | `h21_kappa` |
| opposite sense, r1↑ r2↓ | `B2 ≤ a2+c5` and `B2 ≤ a2+c6+1` | `o1_kappa` |
| opposite sense, r1↓ r2↑ | `B1 ≤ a1+c6` and `B1 ≤ a1+c5+1` | `o2_kappa` |

Transport versions:
- **`o1T_allgaps_iff`.** Exact: every transport behaviour is exclusive at every gap ⟺
  ¬(c5<C6 ∧ a2+c5 < B2). This is the r2→r1 handover's transport condition, because a large
  gap is that handover.
- **`o1T_onset` / `o1T_gap_iff`.** When that condition fails and `b1 ≤ A1−1+C6`, an
  overlapping transport behaviour exists **iff** `e2 − e1 ≥ max(b1−B2+1, a1+c5−B2+1)`.
- **Mirrors.** `o2T_allgaps_iff`, `o2T_gap_iff`.
- **Counter-traces.** `h12_kfail` and `h21_kfail` give a transport counter-trace when the κ
  fails and the q windows can be ordered the wrong way.

Plain language: the race is safe if the holder's request fall reaches its grant output no
later than the fastest path through the state node (ustate read, then q to the OTHER
output). Without FIFO this must hold for both q paths (up to 1 ps). With FIFO it is needed
only when the q→O5/O6 windows allow the bad ordering.

## Part 2: the 36 routed gcd_hw arbiters

### Rows

There are 252 rows: 36 arbiters × 7 rows each, Int ps.

Point corners:
- **Rows.** FMIN, FMAX, SMIN, SMAX.
- **Hull.** `[⌊Σ⌋, ⌈Σ⌉]` of each read's one-corner sum (H_ONE_CORNER plus rounding).

Corner ranges:
- **FR** = `[FMIN, FMAX]`, **SR** = `[SMIN, SMAX]`.
- Each read lies anywhere in its range, independently.

**BOX** = `[⌊FMIN⌋, ⌈SMAX⌉]` (H_INDEP).

Read sums:
- `a_k = rs_k + aq`
- `l = cq + qs + aq`
- `b1 = rg1 + ag1r`, `b2 = rg2 + ag2`
- `c5 = cq + qgw + pqg + ag1q`, `c6 = cq + qgw + pqg + ag2`

Named hypotheses on the rows:
- **H_R_SPLIT.** The r_k net's shared prefix delivers a clean step, so it cancels.
- **The q prefix.** `cq` is counted in every q read, independently. This is the worst case:
  O5 and O6 really share the q pin.
- **H_A0_LOW and H_RST_LOW.** The ustate pins I4 and I3 are 0 during the race. The gcd
  INIT FFF0FFB2 then equals `stF`. This is the bare cell race. The A0-held handover belongs
  to RT1/RT2 (OnGcdArbFix, OnGcdArbA0).

### What is proved

**`gcd_rows`.** On every row, each of the 4 checks (h12, h21, o1 at all gaps, o2 at all
gaps) is DECIDED, in one of two ways:
- **Safe for every per-pin behaviour** (the κ holds, so no FIFO is needed);
- **A FIFO (transport) behaviour overlaps.** For o1/o2 this comes with the exact
  overlapping gap set `e2 − e1 ≥ onO1`, resp. `e1 − e2 ≥ onO2`.

The Python generator also cross-checks every verdict against a brute-force evaluation of
ArbPin's windows over gaps in ±2500 ps.

### Results

| rows | safe without FIFO | needs H_PIN_FIFO | fails even with FIFO |
|---|---|---|---|
| point corners (144) | **all 4 checks, all rows**; min κ margin **54 ps** (`pt_safe`) | 0 | 0 |
| FR / SR ranges (72) | all except one arbiter; min margin of the rest **33 ps** (`rng_safe_margin`) | 0 | seed 2 merge3.uarb1, h21 and o1 (onset at gap 130 FR / 288 SR) (`rng_rows`) |
| BOX (36) | 2 arbiters fully safe (seed 2 merge11.uarb1, seed d merge6.uarb1) | 0 | h12 30, h21 29, o1 29, o2 30 (`box_counts`) |

The failing range rows: k21 = −9 ps (FR) and −30 ps (SR). In the BOX, the smallest of an arbiter's four κ
margins runs from −631 to +118 ps.

### Why H_PIN_FIFO never matters here

- **Point rows.** Every window has at most 2 instants (`pt_narrow`). No runt is possible,
  and the per-pin window equals the transport window.
- **Range and box rows.** Both q orderings are allowed (c5 < C6 ∧ c6 < C5), so transport
  already admits the bad ordering.

Either way the κ inequality decides the verdict. The non-FIFO effect found by ArbPin
(`h12_differs` / `h21_differs`) needs **C5 ≤ c6** (or C6 ≤ c5) together with a wide request
window. No routed row has that combination.

## Findings for the cell owner

1. **seed 2 `merge3.uarb1`.** The r2→r1 handover is safe at every point corner, with κ margin
   56/62/121/138 ps at FMIN/FMAX/SMIN/SMAX. It fails, **even with FIFO pins**, once each
   read varies independently inside one corner's [min, max] range:
   - FR: k21 = a2 + c5 − B2 = 116 + 203 − 328 = −9 ps;
   - SR: k21 = 306 + 457 − 793 = −30 ps.

   The cause is that r2 enters ustate on fast pin A5 (rs2 71..89 ps) but enters ugrant on
   A1 (rg2 218..272 ps). The ugrant path is longer by ~150-400 ps (FAST-MIN to SLOW-MAX),
   and q's path is ~200-560 ps.

   Whether this route is safe therefore depends on how the corner model correlates
   delays within one chip: shared corner plus scatter (shard A's κ / CornerNat), not one
   point. The same row in the full independent box is −474 ps.
2. **The independent box condemns 34/36 arbiters**, even with FIFO. This is the earlier
   corner-mix lesson: the box is not a chip.
3. **H_PIN_FIFO changes no verdict** on these routes. The per-pin model's loss of the C5 ≤ c6
   break-before-make protection is real (ArbPin) but has no instance here.
