Builder.  Up(e0 -> e) is AND-OR as in UpOKA.  Each cause or previous event uses the first clause that holds:
  (U) Up e0 p + hi', (S) a Sep23 entry p -> e0 gives hi', or (R) min over anchors a of Up(a -> p) - Sep23(a -> e0) + hi'.
  The anchors a are the 64 newest per-node common ancestors of p and e0.  The best 16 that have a Sep23 to e0 are tried.
  Up(a -> p) is computed recursively with no depth limit.  This terminates because tm(a) < tm(e0).
  Every value keeps its justification.  The emitter keeps the smallest value per Up key and the largest per Sep key.
  These lookups are monotone, so one value per key is enough.
  The relative clause is used only for guard-end Seps that fail without it (cost: about 40 min per corner).
  Every emitted table passed the checker: 0 upFormB failures and 0 sepFormB failures.  GuardTime recomputed from the emitted
  tables agrees with datal on all 264 guards at both corners.
