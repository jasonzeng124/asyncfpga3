Per kernel: exitcond count minus default count, for every op except fork / buffer / sink / source / constant / join /
ext / trunc (constants listed by their value where they change). Only counts: an operand change with the same ops
(isprime) shows as an empty row.
Reading: in 35 of the 37 kernels the knob turns loop-exit compares into `ne` (slt / ult -> ne); isprime keeps its op
counts (a compare reads a different fork output; proved in A28); dot2 / gather / memsum also gain a minui trip count with a guard. gcd is the exception: it gains NO `ne` test; its one change is
cmpi12 slt -> ult (the inner shift loop's `d < 1`), which LLVM derived from nsw (no signed overflow). That is the
change that makes gcd's knob graph a different function on (2147483647, -1) (FOR-RESEARCH A28). By counts, no other kernel shows
a signed -> unsigned compare change (counts cannot exclude one hidden behind a matching ult -> ne).
