WHAT THIS DOES NOT SHOW
  * No board.  Whether silicon passes a 200-800 ps pulse on sel[k] into a C-element is BOARD-QUEUE item 2 (H_RUNT); the gate's
    model rejects pulses shorter than the receiving C-element's loop, so every GLS here passed its answers.
  * No wrong answer: every bdc_muxnN on these routes is a merge of exclusive branches (an exit mux, an if-else chain), so the
    input whose decode pulses holds no token.  A bdc_muxnN where it can (a loop body run ahead by a later iteration's token, a
    loop header with more than two entries) would turn the same pulse into a mis-steer; none was found or built here.
  * Only the setup side.  The decode must also keep its index until ctl_req has fallen at EVERY decode LUT; the next index
    reaches it only after ctl_req's fall at the selected decode, the join, the mux's delay, the downstream acknowledge, the
    select link's next request -- a whole handshake, against the skew of one net's fall between decode LUTs.  Argued, not
    measured.
  * One route per kernel for every routed claim except the isprime iteration sweep (11 routes of one seed); 2 GLS draws per
    A/B (20001, 20002).  cmpchain: one route per seed (s2 it 5, s3 it 2; s2 it 1 for the mechanism), one rebuilt with the
    guard (s2).  sobel not routed (no route or loop state to rebuild).
  * The rows inherit rule E's launch pessimism (section 12); the margins are rule E's, not a separate model's.
  * isprime it 5 stalls in GLS at draw 20001 on its own flagged races (section 7): recorded, not investigated.
