## I. seeds_fid.py judge accepts a vector that stalls without an error (research @4b922e9b, cells/gls/fid/seeds_fid.py:101-107)
A vector counts as "done" iff laps > 0 and RESULT is "timeout". The run verdict is PASS iff all 16 are done and the
summed errs == 0. A design that completes one lap and then deadlocks on every vector, with no wrong compare, ends
every sim at the timeout with laps >= 1 and errs 0, and so is graded PASS. A real instance: my BQ#2 seed-6 2x draw-2
run (audit/r23/s6_2x_d2.log), vec 0: laps=2 errs=0 oks=2, last lap at 0.49 us, then nothing until TEND = 30 us. It
would be "done" under this judge. That run is a FAIL only because other vectors have errs. The TSVs record laps only
for v6/v12/v13, so a stall on another vector in a reported PASS row would not show there.
Impact on reported results: in every run I reproduced myself (seed 6 1x, seed 4 SLOW_MAX, seeds 7/8 2x, the uori3
fix), every vector has many laps; the lowest in each run is listed in the journal. So none of the PASS rows I
re-ran hides a stall. The PASS rows I did not re-run are covered by this judge only, and the weakness is
unbounded for them.
Verdict: defect in the research judge (OVERSTATED: "PASS 16/16" means "no wrong result, at least one lap", not "no
stall"). Fix would be a minimum-laps or last-lap-time criterion.
