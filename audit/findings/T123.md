## Semantic review (own reading)
* ReqLiveWF says: when r = a and the driver may move, r is not equal to every sharer's ack for ever.
  * With a single sharer it is classically equivalent to ReqLive.
  * On the shared a/b/start request it is exactly the real harness: one flop that moves only when all three acks agree, and then eventually moves.
  * The weakening therefore admits no unrealistic environments.
* Env → EnvWF is proved, so NetCorrectSeqRuntWF → NetCorrectSeqRunt, and every existing refutation carries over (`not_runtWF_of_not`). CONFIRMED.
* Partial hang: `reqLiveWF_partial_ack` proves only that the ReqLive clause is satisfiable there. No full behaviour that satisfies EnvWF ∧ SeqEnv ∧ Behaves ∧ ArbOK on a hang is built. So "a hang is a counterexample instead of a vacuous case" is shown for that clause only (PARTIAL).
* My own extra check: ReqLive and SeqEnv also conflict.
  * Suppose the circuit takes pair k's inputs but never raises out0, and more pairs are offered.
  * ReqLive(Offered n) requires the request to rise, while SeqEnv forbids it (rises(r) > rises(out0.ack)). So Env ∧ SeqEnv is unsatisfiable.
  * This also holds under the WF form (r = 0 = every ack).
  * It is NOT a gap in practice: the instance n = some k has no more pairs to offer, so `more` is false. Env ∧ SeqEnv is then satisfiable, and CircOut's ReqLive catches the output hang.
  * The shared-request partial-ack case differs because its r = true branch needs no `more`, so no finite n catches it. That is why it is a real gap and the WF repair is needed.

## Verdict
* Vacuity proof CONFIRMED.
* Repair sound as a strengthening, and it matches the real harness.
* Its non-vacuity on hangs is shown for the ReqLive clause only.
* Adopting it as THE statement is an owner decision.
