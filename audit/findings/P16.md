(b) What is stated (FiniteNetComb.lean:37-49, FiniteNetBoundA.lean:247-262, 304-341).
- `exc F ps rst t = F (pins at t) (rst t)`: the LUT's zero-delay Boolean function of its pin traces.
- `FCombSpec D L c F ps e Le`: the cell output `O c` is a `Win lo hi` read of `exc` (WinDelay: every output value
  equals the excitation at some instant in `[t-hi, t-lo]`) with H_NO_REVERT, powers up 0, and
  **H_EXC_CLEAN**: `∀ T, (every pin is a GPhT step signal on [0,T) with its driver's edges) → GPhT (exc F ps rst) e Le T`,
  plus H_TIMES/H_CNT/H_FLOOR tying the cell's edge set `L c` to `Le` and its edge times to `e`.
- `GPhT x c L T` (FiniteNet.lean:69-71) only says: x is 0 before edge 0, and `Vph j` between edge j and edge j+1.
  It has no minimum pulse width.
- `FGcdNetOKBA` adds H_ARBQ/H_ARBR/H_ARBG (`∃ ps e Le, FCombSpec … qF/r0F/gF …`), H_ARBA (FMuxASpec) and H_DRV_ARB.
  `qF`, `r0F`, `gF` are `genF bd_arbiter "ustate"/"ugrant"` of the generated netlist.
- `gcd_hw_safe_fin_netBA` is `gcd_hw_safe_fin_netBM … H.toOKBM H_OTHER …`. It still takes
  `H_OTHER : ∀ o, isLink (opAt o) = false → Cell ch (srcV a b) (opAt o)`, and for an amerge `Cell` is
  `∃ g1 g2, CM.AMerge (ch x) (ch y) (ch z) g1 g2` (CapstoneNetDef.lean:384). That is the abstract arbiter with
  `H_ARB1/2`, `H_ARB_EXCL` (never both grants), `xa/ya` (acks only from the own grant and z.ack).
  `toOKBM` uses the arbiter specs only to produce `FCellOK` for the arbiter cells (H_REST), which the BM/B layer
  uses to discharge the LINKS' cell hypotheses.

**H_EXC_CLEAN in plain words:** "if this LUT's input pins are well-formed step signals up to T, then the LUT's
ideal zero-delay output is a step signal up to T whose edges are exactly the listed `e j` (j in `Le`)". Because
`e` and `Le` are existentially chosen per cell (H_ARBQ etc.), and any finite-edge Boolean trace is a GPh for its
own edge list, the field holds for EVERY excitation with finitely many changes, whatever the pins do. Runts
included: a 1-tick pulse is a clean step signal with two edges (`runt_gph`, below). What H_EXC_CLEAN plus
H_CNT/H_TIMES really fix is the bookkeeping: the cell's network edge set `L c` = the excitation's edges, and each
output edge follows its excitation edge within the window. A runt is not excluded here. It just becomes two
more edges that the readers' contracts (ua1/ua2 FMuxASpec, the R0 link, …) would have to absorb.

**Is it an assumption about the arbiter that can fail on silicon?** It is a hypothesis of the theorem. The
theorem's whole arbiter hypothesis set can fail on silicon, but not mainly through H_EXC_CLEAN:
- **Metastability** (bd_arb.v: "metastable q NOT EXCLUDED, at a rate that must be measured") cannot be
  represented. Traces are Bool and `H_LUT_WIN` forces each output value to be some excitation value within a
  bounded window `[lo, hi]`. A metastable level or an unbounded resolution time violates H_LUT_WIN (and the
  Boolean abstraction), not H_EXC_CLEAN. The model excludes it by construction.
- **Double acknowledges** (the board-fidelity GLS at short server times, earlier findings) violate C's
  `AMerge` (`xa/ya`, and `H_ARB_EXCL` if both grants overlap), which is assumed through `H_OTHER`. The
  theorem says nothing about such runs. B's gate modelling does not derive `AMerge` from the INITs. It only
  places the arbiter's cells in the link-binding network.
- The docstrings call H_EXC_CLEAN "where arbitration lives" and "(no runt, no hazard)". The first is fair as
  intent. The second overstates what the field constrains.
