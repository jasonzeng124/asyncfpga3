Transport is admitted. `GateOK p c g x := ∃ f, (∀ i < k, Monotone (f i)) ∧ ∀ t ≥ g.start p, (∀ i < k, f i t ≤ t ∧
Adm p c arc_i (t - f i t)) ∧ x g.out t = g.init.testBit (addr k (fun i => x (ins i) (f i t)))`. Take
`f i t = t - d_i` (truncated at 0): monotone, `f i t ≤ t`, and for `t ≥ g.start p = max ⌈smax·g⌉ >= d_i` the delay is
exactly `d_i ∈ Adm`. The output equation is then literally the simulators' rule (output at t = INIT at the inputs
read at t - d_i); there is no intrinsic output delay and no pulse filter. Spec.lean's own docstring says so: "a read
time that jumps swallows a pulse (inertial behaviour), one that does not jump copies it (transport)". So a 7 ps runt
that circulates for ever is a legal behaviour of the frozen H_PRIM/H_DELAY. Existence of a whole-circuit behaviour
(Behaves quantifies over ALL gates of `circuit N B`, not only the simulated cone): audit/t6/zeroloops.py finds no
cycle of arcs whose Adm interval can contain 0 (`zero-delay cycles found: 0`), so the transport recursion on Nat time
is well-founded and every gate outside the cone also gets a consistent trace.

## 3. What the fid GLS does with a 7 ps pulse (read from /root/wt-r14/cells/gls/{prims.v,fid_core.vh})
- ICBUF (one per routed sink, `-DGLS_TRANSPORT_IC`): `always @(I) o <= #D I;` nonblocking transport: every edge is
  kept; a 7 ps pulse passes any wire unchanged.
- SLICE_LUTX under GLS_FID = FID_LUT6: each pin is a transport copy `aK <= #(T_K - 1) AK`, the output is the zero-time
  mux tree of the delayed pins, followed by FID_SAMPLE (output = f sampled 1 ps after its first change in a step;
  removes only zero-/sub-ps glitches from simultaneous pin updates). A 7 ps runt passes a LUT whose resolver is off.
- FID_RESOLVE (on for a LUT whose output is routed back into its own pin: gen.py sets META6=1, TLOOP6 = feedback wire
  + pin arc, FB6 = feedback pin mask). ua1 = cell c_007111 has `.META6(1), .TLOOP6(1141), .FB6(1)` (feedback on A1).
  With the resolver on, the feedback pin is NOT read from the wire: it is the node's committed state, delivered
  TLOOP after an accepted edge. When the output reverses less than TLOOP after its last edge, the reversal is treated
  as a runt of width p = time since that edge: delta = p - (TLOOP - WIN/2) + N(0, WIN/4) (WIN = TAU = 150 ps
  default); delta <= -WIN/2 -> reversal rejected; otherwise the node goes metastable, holds the new value, and
  commits to the old (delta > 0) or new value after TAU·ln(WIN/(2|delta|)); the committed value goes to fb at once.
  So under the resolver a loop runt never echoes: the transport loop's eternal 7 ps runt CANNOT exist in the
  default fid model (by construction, not by an inertial filter on wires). In the race here, p = 894 ps (ua1's high
  phase, from its rise to the early g arrival), TLOOP = 901, so delta = 68 + N(0, 37.5): metastable, committing to 1
  (stays high) with probability ~0.96 after ~15 ps, otherwise back to 0. The ~15 ps low glitch on ua1 still leaves
  through its other fanout (transport wires).
- `+META_OFF=1` switches every resolver off: pure transport per pin and per wire, i.e. exactly the Spec's
  fixed-read-delay semantics (plus the 1 ps sampler). So a FAITHFUL replay of B's transport behaviour is possible in the
  fid GLS with META_OFF=1, and the default fid (resolver on) shows what the research model predicts instead.
- Delay structure differs: fid LUT O6 arcs are nextpnr's flat 124 ps and the routing carries the rest (e.g. ua1's
  feedback: fid ICBUF 1017 + 124 = TLOOP 1141 at SLOW_MAX; Lean SLOW_MAX: 147+133+138 + 646 = 1064). Only the LUT
  input pin -> output totals matter under transport, so I set the local totals to B's numbers.

## 4. Verdict on the claim as a counterexample to NetCorrectSeq
What is established (by my own code and in the fid GLS):
- The assignment is inside H_DELAY(g = 1, κ, c = 0.5) for κ = 0.215 (per-gate) and 0.158 (per-pin): 0 of 282979 arcs
  outside Adm (exact rationals).
- Fixed per-pin delays are GateOK witnesses (transport); the behaviour exists for the whole circuit (no zero-delay
  cycle).
- In that behaviour ua1 latches a 7 ps (resp. 5 ps) runt that circulates in its 901 ps (859 ps) loop and spreads.
  Reproduced flip-for-flip by my own simulator on my own netlist, and the same runt appears in the fid GLS with the
  resolver off.
- ArbOK(T) holds on the simulated trace [0, 725 ns] for every T >= 422 ps (audit/t6/arbcheck.py; arbiter 0's q
  oscillates from 630 ns but its inputs never stay constant long enough to violate it; the 422 ps comes from power-up
  transients, 374 ps from arbiter 0's own ordinary step at 515 ns, so a theorem with a smaller T is false on every
  trace anyway).
- The env is a SeqEnv (one pair; request 20001-205872 ps, input handshake complete at 275 ns; data held).
What is NOT established: a violation of `Correct`. In the transport trace every boundary node is clean up to the
horizon reached (725 ns, my run; 620 ns, B's): acks rise/fall once, out0_req never rises. The correct run raises
out0_req at 752.97 ns, so neither horizon even reaches the nominal time, and `Correct`'s only possible violation here
is liveness (`CircOut out0 ReqLive`: out0_req must rise eventually), which needs the INFINITE behaviour: no finite
simulation can show it, and the activity keeps growing (4 M node changes per 10 ns at 650 ns, 10 M at 710 ns; 46 M
events by 725 ns), so brute force stops there.
At 725 ns ua1's own loop is empty again (A0 low since 698 ns, ua1 low since 702.6 ns); the runt storm now lives in
g and arbiter 0's state loop. B's README line "the circuit never delivers out0" is therefore UNVERIFIED (and B's
620 ns evidence for it is empty). The claim stands as: "under the frozen H_PRIM, a κ >= 0.158 behaviour exists in
which arbiter 0's handshake turns into a self-sustaining runt storm"; whether that storm ever lets out0 through is
open. Turning it into a Lean-checkable counterexample needs either an invariant proving out0_req stays low for ever,
or (more promising) an adversary that uses Spec's extra freedom (any monotone read time, i.e. inertial swallowing
where convenient) to steer the runt into a finite safety violation, e.g. the out0_req pulse train the fid GLS shows.

Practical consequence for THE goal (decision for A/owner, as B says): at c = 0.5 the race needs κ >= ~0.155 (anti-
correlated scatter between neighbouring arcs); at κ = 0 the g-path exceeds the loop by >= 268 ps. A proof of
NetCorrectSeq at κ >= 0.158 with transport H_PRIM would have to show that this storm always resolves, which is not
credible; the fid GLS (resolver on, i.e. research's best model, which has NO eternal runt) shows a SAFETY failure
(out0_req pulse trains, extra handshakes, then a stall) with the same local delays. So B's "inertial semantics would
recover" is NOT supported by the fid GLS as far as it goes: with research's metastability resolver on the state LUTs
(wires and other LUTs still transport) the circuit still fails. A fully inertial model (pulse rejection on every
LUT/wire) was not tested; neither fid nor the Spec has one.
The theorem's κ must stay below the race threshold (per-corner table in B's README, min 0.145 found at g = 2,
corner 0), or the C-element's timing constraint (feedback loop faster than the g-path) must become an explicit
hypothesis.
