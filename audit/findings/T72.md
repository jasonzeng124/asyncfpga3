# T72 -- BDC_LINK_FASTFALL and research's select rule: does fast fall put the select-path race back?

**Facts read from source (research 7fa9f0c1).**
- bdc/emit.py, under BDC_LINK_FASTFALL=1: every single-stage bd_link gets `.RFAST(1)` (its request delay falls in one hop) and
  every bd_mux gets `.FASTFALL(1)` (its output-request delay falls in one hop). There is no exception for select channels.
  bd_pipe (multi-stage links) is not affected.
- On board item 13's kernel (ipow x0.75 + fast fall + merge link; own emit `/root/t65/gen/ipowfm_kernel_bench.v`): all four muxes
  umux0..umux3 carry FASTFALL(1), and umux1's select link `ulink_n17__1` (a bd_link) carries RFAST(1). On collatz/collatz64,
  umux0's select link `ulink_n14__0` is a bd_link and gets RFAST too.
- RTL rationale (cells/rtl/bd_mux.v:78-82, bd_link.v RFAST header): "z_req's fall carries no obligation -- x/y/ctl data are held
  until their acknowledges fall, which follow the downstream node's fall, which follows this one".
- Research's trace of the collatz64 T4cd seed-7 failure (JOURNAL 2026-11-11 03:10), reproduced by the audit (T65 row 8):
  "umux1's select path (ulink_n14__1, shortened 19 -> 10 ...) lets umux1's request **return to zero early**, ulink_n_falseResult_5
  admits the next token ... inside the counter output's hold window". Research's rule (cc95dc0e, corner_audit fdee9471): never
  shorten a mux delay or a select link's DELAY/SDELAY below base.

**The tension.** Taken as written, the traced mechanism (an early return to zero on a mux's select and request path that breaks a
hold window) is the kind of event that fast fall makes earlier on purpose: a one-hop fall on every mux's output delay and on
bare select links. Either the RTL's "the fall carries no obligation" argument has a gap at muxes, or research's description of
the failure as an early return to zero is imprecise (a shortened bd_pipe also shortens the rise). The select rule as written
covers sizes only, so item 13 (and the pmf / colb candidates) shorten the select path's falling edge without breaking the rule.
