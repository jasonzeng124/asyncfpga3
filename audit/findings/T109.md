Research's sign and size reproduce. Every negative row's shortest path crosses an upstream controller C-element on its
ack input: ulink_n7 via ulink_n12__0's controller (umux0's select link) -> its 1-bit latch -> new select -> umux0's data
LUT -> n7 D (bit 1, 1.6 ns enable wire); the pipe rows via the previous stage's controller -> that stage's latch -> D.
Each is live only if that controller ALREADY holds its next token when the release arrives.

## Dynamic rule H (t109/mon_h.py, own monitor; t109/run_xf4_10.sh)
Per latch bit: at each release (controller node falling, at its driver) arm; t_d = first D-pin change after it, t_c = the
bit's close at its pin; t_d < t_c = HVIOL. At the first state node of each static path: which input changed last at each
output change.
- **Positive control, xf2_1 FAST_MIN (the route that failed, T97): 9/17, HVIOL 2708**, all ulink_n7: "D moved 139 ps
  before close" (= T97's 139 ps setup), the race research's c09dcf51 now locates. The monitor sees a real rule-H failure.
  There too, ulink_n12__0's controller never fired on the ack (entry_last 0 of 2721): the shortest static path is not
  the live one even where the row's location is right.
- **xf4_10 (item 23): 17/17, HVIOL 0 at FAST_MIN, worst+scatter and SLOW_MAX** (~84000 closes of ulink_n7 per corner).
  Min (first D change after release - close), FAST_MIN / worst / SLOW_MAX: ulink_n7 +5188 / +7377 / +15559 ps (static -313);
  trueResult_8 st1 +7225 / +9801 / +21158 (static -112); trueResult_6 st1 +9698 / +13378 / +27929 (static -28);
  trueResult_10 st2 and the n6 / falseResult / trueResult_2 stages: no D change within ~2 ms (one value per invocation).
  At every static path's first controller, the rising (opening) firing NEVER had the ack as its last input (entry_last 0
  of 2575-2624); the controller waited >= 6.9 ns (FAST_MIN) after the ack for its own request.
- Reading: on item 23's route the negative H rows are OR-join artifacts. The upstream controller cannot open until its
  next token arrives, and that token is computed from the value the released latch carries (counter -> select, ring
  stages), so it comes later. Same pattern as T93 for rule E. These timings depend on the handshakes, not on the data
  (one corner = fixed delays), so the vectors cover this mechanism well. A static proof with C-element semantics
  (token causality) is still owed, by research or by the audit.

Verdict: research's H rows on item 23 are **CONFIRMED as computed** (own OR-join reproduces them) and **OVERSTATED as a
hazard**: dynamically rule H holds with >= 5.2 ns at every flagged row and corner, and the static paths are not live. Item
23 stays "gate-clean, dynamically hold-clean, static hold proof OPEN". Items 19 / 22 / 24: not yet checked this way.
Monitor caveat: the HDYN min column printed for xf2_1 (287) misses negative values (unsigned time subtraction); HVIOL
lines are the record of negatives. On xf4_10 there are none, so its minima are exact.
