## Spec draft (formal/lean/Wip/Target/Spec.lean, part I, "unchecked", not frozen)
Read by me against formal/PROGRAM.md "THE goal":
- Inputs: Env requires va k, vb k < 2^31 for every offered k; zero inputs allowed. The kernel (gcd_binary.c as
  reconstructed by C) returns b if a == 0 and a if b == 0, so gcd(0,0) = 0 = Nat.gcd 0 0; consistent. Values
  < 2^31 avoid the documented negative-input loop.
- Pipelining: each input channel follows four-phase on its own (EnvIn: ReqMoves/ReqLive/Offered n), so pair k+1 can
  be offered as soon as pair k's input handshake completes; n = none is an infinite sequence. Matches the
  owner's 2026-10-31 pipelining requirement.
- Safety and liveness: Correct = protocol + liveness on all 5 channels, out0 data = Nat.gcd of the k-th pair while the
  k-th request is high (from Δo after its rise), and for n = some m all boundary nodes eventually low with exactly m
  rises. Matches "safety AND liveness, every input".
- Delays: Adm = one die corner c, band [FAST_MIN/g, SLOW_MAX*g] and local scatter κ around lerp(c); every pin read
  time monotone and admissible (transport and inertial both allowed). Matches H_DELAY(g); note it adds κ, a
  correlation knob that is only a weaker hypothesis for large κ, as stated.
- H_ARB(T): both requests constant on [t1,t2] -> state constant on [t1+T, t2]. A resolution-time bound only, with no
  mutual-exclusion or grant assumption. Matches "internal race resolves within T".
- **H_ENV deviates from THE goal.** PROGRAM.md:55-56 says the harness obeys four-phase "with no timing assumption on
  it". The draft's Env adds two harness timing margins: input data held from `su` ps before each request rise, and
  output acknowledge no earlier than `Δo` ps after the output request rose. The draft states this openly ("no timing
  assumption except two stated margins ... some Δo is inherent at this boundary; the rig pads it with a delay
  line"). su = 0 may be harmless (data valid at the request edge is part of bundled data). But a required Δo > 0 is
  a timing assumption on the harness that the owner excluded. It needs an owner decision or a journaled reason
  before the Spec is frozen.
- Part II (decoder, H_DECODE round trip) is a stub; no theorem about the target exists (STATUS.md says so).
