## Entry trace (trace3, `t94/trace3.sh`)
umux0's entry operand `n_falseResult_3` (the bd_pipe `ulink_n_falseResult_3` output) already carries 0 in batch 4: at its
request rise the latch output still shows 0x40 (batch 3's value) and 2 ns later 0. Upstream, the kernel input n reaches that
pipe's latch D with no storage in between (n_data -> fork -> n1__0 -> D; the request goes fork -> join with ucmpi0's result
-> steer ucond_br4 -> pipe). Batches 0-3 used only bits 1, 2, 4, 6; batch 4 is the first with bit 8. Hypothesis: bit 8 of
the input arrives at the latch after it closes at SLOW_MAX on this route. Trace4 (edges of the bridge's op0_to_core[8] and
the latch output bit 8) running.
