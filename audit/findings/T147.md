Research also says: "no AUTO build has been routed or simulated yet. Sizes are not chosen here."

## Own check (audit/t147/ident.sh, not research's auto_ident.sh)
- Setup: clean worktrees of 26c095065^ and 26c095065. bdc/emit.py on the same input files:
  - 9 kernels' handshake MLIR: collatz, collatz64, fir, gcd, ipow, isprime, single_loop, test_loop_free, xorshift;
  - the 3 hand-recipe pre-pass MLIRs.
- Each run with top and --no-top, under 6 own knob sets: none, BDC_AUTO=0, BDC_AUTO=2, BDC_AUTO=true (all must be OFF), the xorshift recipe, and the collatz recipe.
- **144 cases: 128 outputs byte-identical.** The other 16 fail identically on both sides (exit 1, same EmitError; logs differ only in traceback paths and line numbers):
  - single_loop under every set (mem_controller with a store accessor: not implemented);
  - fir under the recipe sets (BDC_LINK_FASTFALL refused for kernels with memory).
- **Byte-identical when off: CONFIRMED**, including non-"1" values of the switch.

## No instance named: CONFIRMED with one caveat
- bdc/auto.py names kernels and instances only in its docstring (the inventory it replaces) and as labels in the proven-rewrite table.
- The storage rules are graph rules: loop-header control_merges on a cycle, and fork outputs reachable within one iteration.
- **Caveat:** the MLIR rewrites are applied only when the rewritten output's md5 equals one of three files formal proved (xorshift pre_dec, collatz / collatz64 pre_eq2). So on any other kernel no MLIR rewrite applies. This is honest, and stated in the code ("not a general pass"), but it means the rewrite half of "general" covers only those three kernels for now.
