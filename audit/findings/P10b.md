## Details

### 1. prjxray transcription (8cc8788)
`python3 -I audit/P10b/xcheck.py <prjxray-db>/zynq7/timings Formal/Core/Prims/XrayData.lean` prints
`checked 506 numeric mismatches 0 label issues 0`. This covers selmux (18), f7Hop, f8SelHop,
carry4Arc (240, which is every CARRY4* IOPATH in both SDFs: 120+120), lut6Arc, lut5Arc (SLICEM
uses the `LUT_OR_MEM*LRAM` cell type, not SHFREG), outMux, outMuxL, and carryHop. In the SDF file
format, two parenthesised triples on an IOPATH would mean rise/fall. prjxray-db instead fills them
with the fast and slow corners. The Lean reading matches makesdf.py.

### 2. Seq windows
SLICEL REG_INIT_FF: CLK->Q (0.112::0.139)(0.274::0.34), SETUP DIN (-0.055::-0.045), HOLD DIN
(0.194::0.241), SETUP CE (0.088::0.109), HOLD CE (-0.011::-0.009); QL RECOVERY 0.404, QH 0.358,
REMOVAL -0.248. These give dLo=45, dHi=241, ceLo=-109, ceHi=-9, srLo=-404/-358, srHi=-248, which
equals `regFF` (`seq_spot`). FF_INIT and REG_INIT_LAT also agree. SLICEM's flop numbers differ
(diff in scratch). See the table row.
