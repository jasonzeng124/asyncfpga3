# T146: BOARD-QUEUE item 36 (research 0e5fad0c2) -- CARRY4 / MUXF7 ring experiment, pre-run check

Item 36 measures the CARRY4 / F7 delay band that no August kernel can pin (own T145). 64 ring oscillators per bitstream, on two routes (s1 bit 40a85473, s2 19ae3639):
- LUT-only rings;
- rings through 1 / 4 / 16 / 32 CARRY4;
- rings through 8 / 16 MUXF7.

## Own checks (before any board run)
- **Own FF / 5FF-D defect scan** (t67/scan_ff_own.py on the committed .fasm): s1 370 flops, s2 370 flops, MISSING MUX 0 on both. Clean.
- **Prediction table consistent** (research/board/carry/s1/predicted.tsv, own recomputation):
  - Every row satisfies P(x, y) = lo + x·R + y·(C + F), with P(FAST_MIN) = lo and P(SLOW_MAX) = lo + R + C + F, to 2 ps. All 64 rows check; 0 inconsistent.
  - So the fit the item will run is linear in the two bands, as the owner asked (0dacc4e0e).
- **Discriminating power** (from the table): the CARRY / F7 band moves the long rings' period by:
  - C32: 4.31-4.39 ns over y = 0.2 -> 1.0;
  - F16: 5.04-5.08 ns over the same range.
  - That is far above ring scatter (~1 %), so a board run can pin y. Research's stated resolution of +-0.01-0.02 is plausible.
- **Not checked (UNVERIFIED):**
  - the arc-level coefficients (lo, R, C, F) themselves, taken from research's prjxray walk;
  - the claim that the decoded-bits GLS agrees within 30 ps on 96 points;
  - that each ring's chain is the one asked for (check_chains.txt).
- **Verdict:** item 36 is a sound, discriminating measurement of the band that decides item 35 and the x0.55 shrinks. The audit sees no reason to delay it.
