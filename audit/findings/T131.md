# T131: is the audit's T118 negative control (collatz fcsel0 s24, select -> umux1 joins +3000 ps, FAST_MIN "no completion") X propagation?

Research bd57aa13b traced its own select-join injection failures to X from an uninitialized select latch:
* bd_link resets its controller, not its data latch;
* the late select reaches the join after the first request.

Own check:
* t131/mon_x.py logs the first value changes (incl. X) of umux1's join select pins (w15020 / w15026), umux1.either (n3696) and its z_req (n4580).
* Same injected build as T118 (/root/t65/colsel0inj_24), FAST_MIN.
* The monitor flushes and stops the simulation at 5 us. T118's own run printed nothing because the stalled run was killed with its output still buffered.

Trace:
* t = 0: all four nets X. either / z_req go to 0 at 3.3 / 3.8 ns (reset).
* **The select pins stay X until 1 650 493 / 1 650 497 ps.**
* either goes **X at 1 647 703 ps**, before the select is defined; z_req goes X at 1 649 136.
* either -> 1 at 1 650 830, z_req -> 1 at 1 652 263; then both go briefly X again (1 654 113 / 1 654 557) and settle at 0.
* **No further change on these nets up to 5 us.** The run stalls after its first token. The clean route completes all 13 batches by ~60 us.

Verdict:
* T118's "negative control CONFIRMED" is **WITHDRAWN**: the failure begins as X propagation at the first token, because the uninitialized select latch's value reaches the join late. It is not a select-arrival race that silicon (defined power-up value) would show.
* Research's correction (bd57aa13b) is CONFIRMED on the audit's own replay.
* Rule E therefore has no known-bad build, own or research's. Rule M has research's traced wrong-value builds (8745e2d8a), not replayed by the audit.
