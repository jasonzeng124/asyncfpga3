## Claim 1 -- FiniteNet* (Bfin2, 14484c29), FiniteNetWit2*/FiniteNetSrc/FiniteOrN (b8d5ec7b)

Journal 11:11: "fchain_env1 DERIVES each link's FEnv1 on runs that stop;
gcd_hw_safe_fin_chains ... C's terminating run chW meets ALL its hypotheses jointly ...
the first B theorem with derived link environments that has a joint witness on a real gcd
run. Degenerate in three ways (disclosed)".

Plain words. `gcd_hw_safe_fin_chains` (FiniteNet.lean:646) = C's gcd safety, assuming for
EACH link separately `FInChain` (FiniteNet.lean:611): there EXISTS some chain record `D`
(any length, any end-node traces) with this link as cell m+1, whose two END cells satisfy
`SRC_SEG`/`SNK_SEG` (FiniteNet.lean:393-399). Plus C's `H_CELLS` for all 192 non-link
operators (H_OTHER), H_BUNDLE, H_CM_FORCED. Proof is a one-liner to Bfin's
`gcd_hw_safe_fin_links` via `fphysLink_of_inChain` (FiniteNet.lean:625).

Findings:
- `ag_trunc` / `fchain_env1` are genuine generic lemmas (time induction; zero-delay
  counter-example) -- no issue found.
- The end contracts are "conclusion-only": any clean end node satisfies them whatever the
  acknowledge does (SelfAuditB9.seg_of_clean; auditor's `AuditP12b.fchain_src_seg_of_clean`).
  `FInChainC` is a per-link existential: nothing ties link k's chain to link k+1's chain, to
  the netlist's real producer/consumer cells, or to the 100-chain census of
  `AssumeGuaranteeCap`. So H_LINKS is met by any run in which each link's own pins are clean
  step signals with the timing; "FEnv1 derived" is formally true but the derivation is from
  an assumption of the same content (for N = 1 chains, SRC_SEG/SNK_SEG with end node = pin
  shifted one tick IS the request/acknowledge cleanness of FEnv1).
- Witness (FiniteNetWit.lean:203-310): `chD` has `N := 1`, `O 0 := cL x.rq`, `O 2 := cL y.ak`
  (the link's own pin traces one tick early), all delays 1, R = 2. Joint satisfiability is
  real (kernel-checked through Bfin's `lk_all`), but it is a re-labelling of the pins, as the
  self-audit (B-self-audit6.md (a)) says. The journal 11:11 disclosure ("single link ... end
  contracts hold because their conclusions hold ... unit delays") omits that the end nodes
  are not gcd_hw cells at all; self-audit 6 added that.
- Non-degenerate witness? (a) Wiring gate models onto chW is impossible for steers and
  sources: `chW_steer_unwired` (FiniteNetSrc.lean:73; C's steer takes 1 tick channel to
  channel, B's LUT+wire >= 2) and `chW_src_unwired` (:48; a real bd_src re-requests, chW
  stops). Only one firing steer branch is exhibited in Lean (`steer_fires`); "38 of 53" is an
  untrusted Python pre-check. (b) For link-only chains no such obstruction exists on chW
  (C's link is 2 ticks pin-to-pin = B's lo 1 + wire 1), so a multi-link chain witness is
  probably constructible, but it would NOT make the theorem more meaningful: the hypothesis
  quantifies existentially per link, so a longer witness chain does not strengthen what the
  theorem asserts. Non-degeneracy would need a hypothesis that binds chain end cells to the
  netlist's cells (shared across links); none exists. Auditor did not build a multi-link
  witness (cost vs. value; see the above argument).
- `gcd_hw_fin_net_witness` (FiniteNetWit2): joint but decoupled, exactly as disclosed: every
  channel signal is driven by a pinless contract cell (`pR`/`pA`, FiniteNetWit2.lean:72-73),
  gate-modelled nodes drive nothing.
- FiniteOrN: `or3_init_unique` (FiniteOrN.lean:272) is true and trivial (decide over 256
  INITs); `gcd_hw_safe_fin_net3'` carries the same driver caveat (stated in journal).

Verdict 1: OVERSTATED (theorems hold as implications; "FEnv1 derived" and "first theorem with
derived link environments that has a joint witness" overstate: the derivation is from
per-link free end contracts equivalent in content to FEnv1, and the witness is a
re-labelling). The same weakness applies to Bnet's earlier `gcd_hw_safe_chains`
(AssumeGuaranteeCap.lean:115 `InChain`, same per-link existential and same SRC_SEG shape,
AssumeGuaranteeLinks.lean:328), whose journal entry (JOURNAL-B.md:1126-1127, "the 175 links
form 100 chains ... gcd_hw_safe_chains derives every link's Env1 from chain-end contracts")
suggests the census chains are used; they are not. Self-audit 6 does not extend its
re-labelling finding to Bnet.
