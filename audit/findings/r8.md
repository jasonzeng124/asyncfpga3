## Details

### 1. CARRY4/SLICE_LATX transport (78de9c2)
- Compile: `iverilog -gspecify [-DGLS_FID] -I<gls> tb.v <gls>/prims.v`. The outputs are in `audit/r8/glsx/log/*.out`.
- The fid CARRY4 has one delayed copy of each pin per output (arc − 1 ps), and FID_SAMPLE adds the 1 ps back. The functions match the default model's.
- gen.py bakes the same `T<pin><out>` parameter names. The fid latch evaluates once per time step, 1 ps after the first delayed pin moves.
- An evaluation in the active region runs before the same-step NBA pin updates, and those updates re-trigger the block. So an edge that lands exactly at evaluation time is not lost. It is delayed by 1 extra ps (code reading).

### 2. DSP48E1 (14d7b81 / 007e895)
- Reference: `/root/audit-tc/openxc7/share/yosys/xilinx/cells_sim.v` (md5 6f92cccf…), module DSP48E1 copied to `r8/dsp/yosys_dsp48e1.v` with `$fatal` turned into `$display`.
- Yosys's ALU is the same carry-save structure. In logic modes it gates CIN to 0, and research refuses CARRYIN=1 in a logic mode, so the two agree.
- Yosys treats Y=M as 0 and puts the whole M on X, which is research's assumption too. This agreement shows that research matches yosys. It does not show that either matches silicon for partial products. Research's MUNK=x is the conservative choice there.
